# 원격 MCP 스크립트 / 로컬 실행공간 개편

## 보존 계약

기존 canonical, 원문, 공개 HTML/PDF, 템플릿, 컴파일러, 검증기, 페이지 규칙을 수정하지 않는다. 기존 산출물의 SHA-256을 기록하고 완료 시 전수 재검사한다. 같은 canonical으로 기존 엔진과 원격에서 받은 실행 패키지의 IR/HTML을 비교한다. PDF는 브라우저·폰트·생성시각에 의존하므로 기존 PDF 바이트 보존과 새 PDF의 레이아웃 검증을 구분한다.

## 구조 비교

| 구조 | 장점 | 출력 보존에 대한 위험 | 선택 |
|---|---|---|---|
| 서버가 PDF까지 모두 생성하고 다운로드 | 로컬 설치 최소화 | 서버 OS·폰트·브라우저 차이로 줄바꿈과 측정값이 바뀔 수 있음 | 보류 |
| 원격 컴파일 + 로컬의 별도 렌더러 | 역할 분리 | 양쪽 렌더·릴리스 구현이 갈라지고 기존 QA 계약을 재구현해야 함 | 보류 |
| 원격 MCP가 고정 버전 실행 패키지 제공 + 로컬이 원래 엔진 실행 | 엔진 파일 그대로 사용, 같은 로컬 브라우저·입출력·QA 유지 | 원격 패키지 신뢰와 해시 고정 필요 | 채택 |

원격 서버는 규칙, 스키마, 엔진, 템플릿의 배포 원본을 소유한다. 로컬 클라이언트는 HTTPS MCP 인증, 고정 해시 검증, 캐시, 프로세스 실행만 담당한다. 로컬 input/outputs/others 구조를 유지한다. 서버 장애 시 기존 엔진으로 조용히 대체하지 않는다. 기존 엔진 소스는 서버 패키징·비교 검증을 위한 개발 원본으로 남긴다.

## 순차 실행 계획

1. [x] 기존 모든 자료·결과·실행 코드의 SHA-256 기준선과 기존 테스트 결과 저장.
2. [x] 변경 없는 실행 파일을 allowlist로 묶는 결정론적 runtime 패키지와 릴리스 lock 생성.
3. [x] 인증된 FastMCP HTTP 서버: guidance, runtime manifest/download, 검증/컴파일 도구 구현.
4. [x] 표준 라이브러리 로컬 클라이언트: 프로젝트 .env, MCP handshake, 고정 해시·경로 검증, 캐시 설치, 로컬 실행 구현.
5. [x] 기존 작업공간 경로를 사용하는 runtime 진입점과 프로젝트 스킬·사용법 작성. prepare/시각검수/publish 분리 유지.
6. [x] 기존 테스트, 원격 전송·인증·변조·경로탈출 테스트, 실제 canonical을 이용한 HTTP 실행과 결과 비교.
7. [x] 기존 파일 전수 해시 재검사, 최종 서버 패키지, 로컬 HTTP 실검증 및 보고서 완료. 사용자 승인 후 HTTPS 배포와 실제 결과 생성·검수·저장을 완료했다. 최신 증거는 ../reports/remote-mcp/DEPLOYED.md에 있다.

## 검증 기록

최종 증거와 재개 지점: [검증 보고서](../reports/remote-mcp/RESULT.md).
