# AGENTS.md — 기존 자료 폐쇄형 7단계 영어 WORKBOOK 제작 지침

> 이 지침은 사용자가 제공한 원본 문제, 10단계 WORKBOOK, 지문분석본, 어휘 참고 AGENTS, HTML 디자인 템플릿, 채팅 지시를 바탕으로 **학생용 문제지**와 **교사용 해설지**를 제작하기 위한 작업 규칙이다. 핵심 원칙은 “기존 자료의 허용 요소는 빠짐없이 포함하고, 기존 자료 밖의 요소는 쓰지 않는다”이다.

---

## 0. 최상위 원칙

### 0.0 작업 수신 즉시 적용 규칙

새 작업물이 들어오면 아래 순서를 먼저 수행한다.

1. 사용자가 제공한 사진, 이미지, PDF, 문서, 텍스트, 채팅 자료가 실제로 추출 가능한지 즉시 확인한다.
2. 사진·스캔 자료는 육안 판독 가능 범위, OCR 가능 여부, 기존 텍스트 자료와 대조 가능 여부를 먼저 점검한다.
3. 추출이 불명확한 부분은 임의로 만들지 않고, 판독 가능한 범위와 불확실한 범위를 분리한다.
4. 자료 추출 가능성이 확인되면 이 `AGENTS.md` 지침과 제공 HTML 템플릿을 기준으로 바로 산출물 제작에 들어간다.
5. 최종 작업물은 마크다운 본문 답변으로 대체하지 않고, 요구된 HTML과 PDF 파일 형태로 생성한다.
6. 입력 자료가 부족해 유지 7단계 전체를 원본 그대로 복원할 수 없을 때도, 기존 자료에서 확인되는 요소만 사용하고 자료 밖 문항·해설·어휘를 추가하지 않는다.

### 0.1 절대 조건

1. 최종 산출물은 반드시 아래 4개 파일이다.

   ```text
   outputs/<작업폴더명>/문제.html
   outputs/<작업폴더명>/문제.pdf
   outputs/<작업폴더명>/해설.html
   outputs/<작업폴더명>/해설.pdf
   ```

2. 원본 10단계 WORKBOOK 중 최종 산출물에 포함할 단계는 **W1·W4·W6·W7·W8·W9·W10**이다.
3. **W2·W3·W5는 최종 산출물에서 제거**한다.
4. 문법은 사용자가 지정한 **8개 요소만** 다룬다.
5. 어휘는 사용자가 제공한 어휘용 `AGENTS.md`와 `index.template.html`의 **출제 수준과 레이아웃**만 참고한다.
6. 모든 산출물은 `outputs/<작업폴더명>/`에 저장한다.
7. `문제.html`에는 W1 해석본의 `정답 확인`을 제외한 정답·해설·숨김 정답 데이터가 들어가면 실패다. W1은 기존 해석본을 그대로 이식하는 단계이므로 원본 문항의 확정 답을 화면에 직접 표시하며, 숨김 데이터로만 넣지 않는다.
8. `해설.html`에는 정답·근거·어휘 정답·허용 문법 범위 내 해설이 들어가야 한다.
9. PDF는 각각 대응 HTML에서 생성한다.
10. 기존 자료에 없는 문제, 문법, 예문, 배경지식, 디자인 요소, 파일 구조를 추가하지 않는다. 단, W1 해석본의 의미 단위 분절, 한국어 대응 해석, 핵심 동사 표시, B2 이상 핵심 어휘 선정과 작은 뜻, 주제 한 문장, 원본 문항 정답 확정은 기존 해석본의 필수 분석 기능이므로 원본 지문과 선택지에서 직접 생성한다.
11. 각 A4 페이지 하단 우측에는 윤조교 로고 푸터를 작게 넣는다.
    - 로고는 본문 카드·표·답안칸 안에 넣지 않고, 얇은 구분선으로 분리된 전용 푸터 행에 둔다.
    - 기본 크기는 높이 `5.5mm`, 너비 자동, 최대 체감 폭 `15mm~18mm` 수준으로 유지한다.
    - 템플릿 기준 로고 파일은 `assets/yonjogyo-logo-footer.png`를 사용하고, 출력 폴더에는 필요 시 같은 자산을 복사해 HTML 경로가 깨지지 않게 한다.

### 0.2 폐쇄형 소스 원칙

이 작업은 **source-closed** 방식으로 수행한다.

```text
최종 산출 요소 = 기존 자료에서 추출한 요소 - 사용자 제거 요소 - 금지 요소
```

따라서 다음 두 조건을 모두 만족해야 한다.

1. 기존 자료에 있는 **허용 요소**가 누락되면 실패다.
2. 기존 자료에 없는 **임의 요소**가 추가되면 실패다.

W1 해석본 예외:

- W1은 `../해석본 agent/AGENTS.md`의 일반 의미 단위 해석본을 먼저 완성한 뒤, 그 해석본 파트를 워크북에 그대로 이식한다.
- 원문에서 직접 판독·분석한 `en`, `hint`, 핵심 동사, B2 이상 핵심 어휘와 작은 뜻, `topic`, `answer`는 임의 외부 요소가 아니라 W1 해석본의 필수 파생 데이터로 인정한다.
- 이 예외는 W1에만 적용한다. W4·W6·W7·W8·W9·W10의 문제·해설·어휘·문법 요소는 계속 source-closed 원칙을 따른다.

### 0.4 충돌 처리 우선순위

자료끼리 충돌하면 아래 순서로 판단한다.

1. 사용자의 최신 채팅 지시
2. 원본 문제
3. WORKBOOK 정답부
4. WORKBOOK 본문
5. 지문분석본
6. 어휘용 AGENTS.md와 HTML 템플릿
7. 이 AGENTS.md의 일반 운영 규칙

예외 처리:

- W2·W3·W5는 기존 WORKBOOK에 있더라도 최종 산출물에 독립 단계로 넣지 않는다.
- 지문분석본 CHECK 또는 Grammar+에 8개 허용 문법 밖의 문법이 있으면 문법 문항·문법 해설로 쓰지 않는다.
- 어휘용 AGENTS가 별도 `index.html`, `README.md`, `vocabulary.json`을 요구하더라도 현재 작업의 필수 산출 파일은 `문제.html`, `문제.pdf`, `해설.html`, `해설.pdf`이다.
- 기존 자료에 있는 요소라도 학생용에 노출하면 정답이 드러나는 경우에는 학생용에 넣지 않고 해설용에만 둔다. 단, 기존 해석본을 그대로 이식하는 W1의 `주제 한 문장`과 `정답 확인`은 예외로 문제지에도 표시한다.

## 2. 문법 범위: 8개 요소만 허용

### 2.1 문법 화이트리스트

문법 문항, 문법 해설, Grammar+ 요약, 오답 근거는 아래 8개 요소만 다룬다.

| 번호 | 허용 문법 요소 | 출제·해설 기준 | 예시 |
|---:|---|---|---|
| 1 | 능동 / 수동 구분 | 주어가 행위자인지 대상인지 판단한다. 완료형 능동과 수동태 혼동도 포함한다. | `were discovered` / `have discovered` |
| 2 | 목적어로 to부정사 / -ing를 반드시 받는 동사·표현 | 특정 동사·표현 뒤에 `to V` 또는 `V-ing`가 필요한지 판단한다. | `regret to inform`, `look forward to seeing` |
| 3 | 형용사 / 부사 구별 | 명사 수식이면 형용사, 동사·형용사·문장 수식이면 부사로 판단한다. | `calm` / `calmly` |
| 4 | 명사절 that / what 구별 | 뒤 절이 완전하면 `that`, 불완전하거나 “~하는 것”이면 `what`으로 판단한다. | `that S+V`, `what S+V` |
| 5 | 동사 찾기 → 부사절·부사구 -ing 구별 | 문장 골격의 본동사와 부사 역할의 `-ing` 구문을 구별한다. | `were discovered, causing ...` |
| 6 | which / in which / where / when 구별 | 선행사와 뒤 절의 결손 성분을 보고 관계대명사·관계부사를 구별한다. | `which`, `in which`, `where`, `when` |
| 7 | a few / few / little / a little 등 구별 | 가산·불가산 명사와 긍정·부정 뉘앙스를 구별한다. | `a few`, `few`, `a little`, `little` |
| 8 | 부정어구 / 도치 | 부정어구가 문두에 올 때 도치가 필요한지 판단한다. | `Never have I ...`, `Not until then did ...` |

### 2.2 금지 문법

아래 항목은 기존 자료에 있더라도 독립 문법 문제나 문법 해설로 다루지 않는다.

```text
수일치
시제 일반론
관사
전치사 일반론
병렬연결 일반론
비교급·원급 비교 일반론
대명사 지칭 일반론
who / whose / whom 구별
that / which 일반 관계대명사 구별
on / in 구별
자동사 / 타동사 일반론
분사 형용사 일반론
현재분사 / 과거분사 일반론
가정법 일반론
접속사 일반론
목적의 to부정사 일반론
가주어·진주어 to부정사 일반론
```

### 2.3 CHECK·Grammar+ 선별 규칙

1. 지문분석본의 CHECK와 Grammar+를 먼저 추출한다.
2. 한 CHECK 안에 여러 문법 요소가 섞여 있으면 선택지 쌍 단위로 분해한다.
3. 8개 허용 문법에 속하는 선택지 쌍만 사용한다.
4. 8개 허용 문법 밖의 선택지 쌍은 `excluded`로 기록한다.
5. 금지 문법을 대체하기 위해 자료 밖 문법 문항을 새로 만들지 않는다.
6. 해설은 반드시 8개 허용 문법 명칭 중 하나로 시작한다.

예시 처리:

| 선택지 쌍 | 처리 | 이유 |
|---|---|---|
| `that / what` | 사용 가능 | 명사절 that / what 구별 |
| `told / been told` | 사용 가능 | 능동 / 수동 구분 |
| `unattractive / unattractively` | 사용 가능 | 형용사 / 부사 구별 |
| `seem / seems` | 사용 금지 | 수일치 |
| `on / in` | 사용 금지 | 전치사 일반론 |
| `long / longer` | 사용 금지 | 비교급 일반론 |
| `recognize / to recognize` | 원칙적 사용 금지 | 목적어로 to부정사/-ing를 받는 동사·표현이 아님 |

## 3. 어휘 출제 수준과 레이아웃

### 3.1 어휘 출처 제한

어휘는 아래 출처에 있는 단어·표현만 사용한다.

1. 원문 지문
2. WORKBOOK에 강조된 어휘·표현
3. 지문분석본의 WORDS & EXPRESSIONS
4. 사용자가 제공한 어휘 자료 안의 단어

자료 밖 단어를 새 시험어로 추가하지 않는다. 외부 사전에서 임의로 유의어·반의어 세트를 확장하지 않는다.

### 3.2 어휘 난도

어휘용 AGENTS의 수준을 참고해 두 층위로 구분할 수 있다.

| 분류 | 기준 |
|---|---|
| Regular | 지문 이해에 꼭 필요하고 고1~고2 수준에서 확인할 가치가 있는 어휘 |
| Difficult | 문맥상 중요하고 학생이 놓치기 쉬운 B2~C1 수준 어휘 |

분류도 기존 자료의 어휘를 정리하는 용도일 뿐, 자료 밖 어휘를 추가하는 근거가 될 수 없다.

### 3.3 어휘 테스트 레이아웃

제공된 `index.template.html`의 구조를 참고한다.

- A4 세로 페이지
- 2열 구조
- 각 열 13행
- 한 페이지 최대 26문항
- 각 문항에 영어 단어 제시
- 학생용에는 `발음` 작성란과 `뜻` 작성란 제공
- 해설용에는 `No. / Word / Pron. / Meaning` 정답표 제공
- Brand Red `#ed1c24`는 kicker, note label, answer label 같은 제한된 위치에만 사용
- 일반 번호, 지시문, 본문, 표 라벨은 검정 또는 짙은 회색 사용

학생용에 발음·뜻 정답, 숨김 answer data, HTML 주석 속 정답, `data-answer` 속성을 넣지 않는다.

## 4. 폴더 구조와 저장 규칙

### 4.1 기본 폴더

```text
html(디자인 레이아웃)/
inputs/
outputs/
```

| 폴더 | 역할 | 금지 |
|---|---|---|
| `html(디자인 레이아웃)/` | HTML/CSS 템플릿과 인쇄 레이아웃 기준 | 최종 산출물 저장 금지 |
| `inputs/` | 원본 PDF, 이미지, 텍스트, 워크북, 지문분석본 | 생성물 저장 금지 |
| `outputs/` | 최종 산출물 저장 위치 | 루트에 파일 흩뿌리기 금지 |

### 4.2 작업폴더명 생성

모든 결과물은 `outputs/<작업폴더명>/`에 저장한다.

우선순위:

1. 사용자가 출력 폴더명을 명시한 경우 그 이름 사용
2. `inputs/`에 대표 파일이 있으면 그 파일명 기반 생성
3. 여러 입력 파일의 공통 시험명·범위 기반 생성
4. 채팅창에서 준 자료명·시험명·범위 기반 생성
5. 제목이 없으면 `작업_YYYYMMDD_HHMM` 사용

폴더명 규칙:

- 확장자는 제거한다.
- 공백은 `_`로 바꾼다.
- 경로 충돌 문자 `\ / : * ? " < > |`는 `_`로 바꾼다.
- 너무 긴 이름은 핵심 정보 중심으로 축약한다.
- 같은 폴더가 있으면 `_v2`, `_v3`를 붙인다.
- 서로 다른 시험, 학년, 범위, worksheet family를 같은 폴더에 섞지 않는다.

### 4.3 필수 산출물

작업 완료 조건은 아래 4개 파일의 존재와 정상 렌더링이다.

```text
outputs/<작업폴더명>/문제.html
outputs/<작업폴더명>/문제.pdf
outputs/<작업폴더명>/해설.html
outputs/<작업폴더명>/해설.pdf
```

`assets/` 폴더는 템플릿 실행에 필요한 CSS·이미지 자산을 복사하는 경우에만 허용한다. 별도 학습지 파일인 `index.html`, `README.md`, `vocabulary.json`은 현재 작업의 필수 산출물을 대체할 수 없으며, 사용자가 별도로 요청하지 않는 한 생성하지 않는다.

## 5. 추출 절차와 Source Coverage Ledger

### 5.1 추출 순서

각 지문마다 아래 순서로 자료를 추출한다.

1. 원본 문제에서 번호, 유형, 영어 지문, 선택지, 정답, 빈칸·밑줄·삽입 위치를 추출한다.
2. WORKBOOK에서 W1·W4·W6·W7·W8·W9·W10의 실제 문제 형식과 정답 형식을 추출한다.
3. W2·W3·W5는 제거 대상이므로 추출하되 산출물에는 넣지 않는다.
4. 지문분석본에서 제목, 내용, Flow Check, 문장별 해석, CHECK, Grammar+, 원본 문제, 정답, 오답 풀이, WORDS & EXPRESSIONS, 출제 가능한 유형 CHECK를 추출한다.
5. 어휘용 AGENTS와 `index.template.html`에서 어휘 난도와 레이아웃 기준만 추출한다.
6. 추출한 요소를 Source Coverage Ledger에 등록한다.

### 5.2 이미지·스캔 자료 3회 점검

이미지나 스캔 PDF에서 원문을 추출할 때는 다음 3회를 모두 수행한다.

| 차수 | 점검 내용 |
|---:|---|
| 1차 | 화면에서 영어 본문을 직접 읽어 초벌 원문을 만든다. |
| 2차 | OCR 또는 기존 텍스트와 대조해 단어, 문장부호, 대소문자, 줄 순서, 빈칸·밑줄 위치를 확인한다. |
| 3차 | 출력 HTML에서 태그를 제거한 영어 텍스트와 확정 원문을 비교한다. |

OCR 결과만 믿고 원문을 확정하지 않는다.

### 5.3 Source Coverage Ledger

각 지문마다 내부 검수용 Ledger를 작성한다. 이 Ledger는 산출물 생성 여부를 판단하는 기준이다.

| 필드 | 의미 | 예시 |
|---|---|---|
| `source_id` | 자료명·쪽수·섹션 | `WORKBOOK p.1 W1`, `지문분석 p.2 CHECK 4` |
| `source_element` | 기존 자료에서 확인한 요소 | `Flow Check 전개`, `that / what 선택지`, `WORDS: delay` |
| `status` | 포함·제외·참고 상태 | `included`, `excluded`, `reference_only` |
| `output_location` | 반영 위치 | `문제.html W6-2`, `해설.html W1 정답 근거` |
| `exclusion_reason` | 제외 사유 | `W2 제거`, `문법 8요소 밖`, `학생용 정답 노출 위험` |

상태 판정:

| status | 뜻 | 처리 |
|---|---|---|
| `included` | 현재 규칙상 사용할 수 있고 산출물에 넣어야 하는 요소 | 문제지 또는 해설지에 반영 |
| `excluded` | 기존 자료에 있지만 사용자 지시 또는 금지 규칙으로 제외되는 요소 | 산출물에서 제외하고 사유 기록 |
| `reference_only` | 직접 문제로 넣지는 않지만 레이아웃·검수·해석 기준으로 쓰는 요소 | 직접 노출하지 않거나 간접 반영 |

### 5.4 Ledger 예시

```json
[
  {
    "source_id": "WORKBOOK p.1 W1",
    "source_element": "영어 원문과 한국어 해석 병렬 제시",
    "status": "included",
    "output_location": "문제.html W1 / 해설.html W1"
  },
  {
    "source_id": "WORKBOOK p.2 W2",
    "source_element": "우리말 빈칸 완성",
    "status": "excluded",
    "exclusion_reason": "사용자가 W2 제거를 지시함"
  },
  {
    "source_id": "지문분석 p.2 CHECK 5",
    "source_element": "on / in 선택지",
    "status": "excluded",
    "exclusion_reason": "문법 8요소 밖의 전치사 일반론"
  },
  {
    "source_id": "index.template.html",
    "source_element": "A4 2열 13행 발음·뜻 작성란",
    "status": "reference_only",
    "output_location": "문제.html 어휘 미니 테스트 레이아웃"
  }
]
```

### 5.5 Ledger 검수 원칙

- `included` 요소는 실제 문제지 또는 해설지에 반영되어야 한다.
- 출력물 안의 모든 문제·해설·어휘·문법·배열·영작 요소는 Ledger의 어느 한 항목과 연결되어야 한다.
- Ledger에 없는 출력 요소가 발견되면 기존 자료 밖 요소로 보고 삭제한다.
- 기존 자료에 있으나 제외한 요소는 반드시 `excluded` 또는 `reference_only`와 사유를 기록한다.
- `included` 요소가 빠졌거나, 출처 없는 요소가 들어가면 HTML/PDF 완료 처리를 금지한다.

## 6. 제작 절차

각 지문은 아래 순서로 제작한다.

1. 번호 범위와 입력 자료를 확인한다.
2. 입력 파일명 또는 채팅 자료명을 기준으로 `outputs/<작업폴더명>/`을 만든다.
3. `html(디자인 레이아웃)/`의 템플릿을 확인한다.
4. 원본 문제, WORKBOOK, 지문분석본, 어휘 참고 자료를 확인한다.
5. W1·W4·W6·W7·W8·W9·W10 요소를 추출한다.
6. W2·W3·W5 요소는 제외 사유와 함께 Ledger에 기록한다.
7. CHECK와 Grammar+를 선택지 쌍 단위로 분해하고 8개 허용 문법만 남긴다.
8. WORDS & EXPRESSIONS와 원문 어휘를 추출하고, W1용으로 원문 모든 문장의 B2 이상 핵심 어휘를 전수 검토한다.
9. Source Coverage Ledger를 작성한다.
10. 학생용 `문제.html`을 제작한다.
11. 교사용 `해설.html`을 제작한다.
12. `문제.html`에서 `문제.pdf`를 생성한다.
13. `해설.html`에서 `해설.pdf`를 생성한다.
14. 네 파일 존재, source coverage, W1 해석본 전체 기능, W1 이외 단계의 정답 비노출, 제거 단계 혼입, 문법 범위, 레이아웃, PDF 렌더링을 검수한다.
15. 실패 항목이 있으면 HTML/CSS/내용을 수정하고 PDF를 다시 생성한다.

## 7. 유지 7단계별 세부 제작 지침

각 단계는 `출처 기준 → 학생용 구성 → 해설용 구성 → 금지 요소 → 예상 오류 → 검수` 순서로 점검한다.


### 7.0 단계별 세부 항목 보존 인벤토리

아래 인벤토리는 각 단계에서 **기존 자료에 있으면 반드시 추출·반영해야 하는 최소 단위**이다. 단, W2·W3·W5와 8개 허용 문법 밖의 문법 요소는 기존 자료에 있어도 산출물에 넣지 않고 Ledger에 `excluded`로 기록한다.

#### 공통 페이지 요소

모든 유지 단계는 기존 WORKBOOK 또는 제공 HTML 레이아웃에 있는 아래 요소를 보존한다.

- 시험명, 학년, 지문 번호, 원본 문항 유형
- `WORKBOOK` 라벨과 원본 단계 번호·단계명
- 원본 지시문
- 문장 번호와 각주 번호
- 원본 영어의 대소문자, 문장부호, 줄 순서, 문단 구분, 밑줄·빈칸·괄호·대괄호·화살표·라벨
- 기존 자료의 강조 어휘·표현 표시
- 답란의 위치와 성격: 해석 작성란, 선택형 괄호, 오류 수정란, 배열 답란, 영작 빈칸
- 제공 레이아웃에 있는 A4 인쇄 구조, 테두리, 열 구조, 표 구조, 필기선

공통 금지:

- 기존 자료에 없는 단계 설명, 난도 표시, 별점, QR, 아이콘, 추가 지시문, 추가 문제 번호를 만들지 않는다.
- 기존 자료에 없는 예문, 배경지식, 주제문, 문법 설명, 어휘 확장을 넣지 않는다.
- 문제지에는 정답성 단서가 되는 해설 박스, 정답 번호, 오답 이유, 배열 정답, 영작 모범답안을 넣지 않는다.

#### W1 지문 연습하기 세부 항목

W1은 기존 자료의 “영문과 우리말 해석을 읽으며 지문의 내용을 파악하는 단계”인 동시에, `../해석본 agent/AGENTS.md`로 만든 일반 의미 단위 해석본 전체를 워크북 안으로 그대로 이식하는 단계다. 단순한 영문·번역 병렬표로 축소하지 않는다.

반드시 추출·반영할 항목:

- `WORKBOOK 1 지문 연습하기` 단계명
- “영문과 해석을 읽고 문장의 의미를 이해해 보세요.”에 해당하는 원본 지시문
- 영어 원문 전체
- 주어 / 핵심 동사 / 목적어 / 보어 / 부사구·부사절 기준으로 분절한 `en` 전체
- `en`의 각 슬래시 단위와 1:1로 대응하는 한국어 `hint` 전체
- 각 영어 단위 바로 아래에 한국어 단위를 중앙 정렬해 붙이는 기존 해석본 구조
- 문장 골격을 이루는 핵심 서술어의 굵게·밑줄 표시
- 문장별 B2 이상 핵심 어휘 1~3개, 영어 작은 뜻, 영어·한국어 동일 색 클래스
- 지문 전체의 `주제 한 문장`
- 원본 문항 유형에 맞게 확정한 `정답 확인`
- 문장·문단 순서
- 편지글의 수신 인사, 본문, 맺음말, 서명 등 장르 요소가 있으면 그대로 보존
- 기존 강조 어휘·표현과 해석본이 전수 검토해 선정한 B2 이상 핵심 어휘
- 지문분석본에 있는 제목, 한국어 제목, 내용 요약, Flow Check는 별도 분석 요소로만 반영하고 새 요약을 만들지 않음

문제지 처리:

- 완성된 기존 해석본 페이지를 W1에 그대로 제시한다. 의미 단위 원문, 단위별 한국어, 핵심 동사, B2 이상 어휘 작은 뜻, 주제 한 문장, 정답 확인을 생략하지 않는다.
- W1의 `정답 확인`은 기존 해석본 기능이므로 문제지에 직접 표시한다. 오답 풀이와 장문의 정답 근거는 해설지에만 둔다.
- W1에 기존 자료에 없는 “주제 찾기”, “목적 쓰기”, “핵심 문장 고르기” 같은 새 활동을 추가하지 않는다.

해설지 처리:

- 문제지 W1과 같은 완성 해석본을 제공하고, 의미 단위·핵심 동사·어휘·주제·정답 표시를 그대로 유지한다.
- 지문분석본의 제목, 내용, Flow Check, 원본 정답, 정답 근거, 오답 풀이가 있으면 기존 문구 범위에서 반영한다.
- 자료에 없는 추가 배경 설명이나 문법 강의는 넣지 않는다.

#### W4 해석 연습하기 세부 항목

반드시 추출·반영할 항목:

- `WORKBOOK 4 해석 연습하기` 단계명
- “문장 전체의 자연스러운 해석을 써 보세요.”에 해당하는 원본 지시문
- W1과 같은 문장 번호
- 영어 문장 전체
- 문장별 해석 작성 공간
- 원본 각주 번호와 문장 나눔 방식

문제지 처리:

- 영어 문장과 빈 작성란만 둔다.
- 완성 해석, 정답 힌트, 문법 설명은 넣지 않는다.

해설지 처리:

- 문장별 자연스러운 해석을 제공한다.
- 수치, 날짜, 부정, 대조, 인과, 조건, 지시 대상은 원문과 지문분석본 범위 안에서 확인한다.

#### W6 어법·어휘 고르기 세부 항목

반드시 추출·반영할 항목:

- `WORKBOOK 6 어법·어휘 고르기` 단계명
- “괄호 안에서 옳은 어법과 어휘를 골라 보세요.”에 해당하는 원본 지시문
- 한국어 의미 단서가 있으면 그대로 반영
- 원문 기반 영어 문장

## 8. 공통 요소 반영 규칙

### 8.1 제목·내용·Flow Check

- 지문분석본의 제목과 한국어 제목을 기준으로 한다.

- Flow Check는 도입·전개·마무리와 문장 번호 범위를 보존한다.
- 장문은 지문분석본에 있는 문단 기능만 반영한다.
- 자료에 없는 새로운 주제문이나 해석 관점을 만들지 않는다. 단, W1의 `주제 한 문장`은 기존 해석본이 원문 전체와 정답 선택지 성격을 분석해 직접 확정하는 필수 기능이므로 생성한다.

### 8.2 원본 문제와 정답

- 원본 문제의 선택지와 정답을 해설용에 반영한다.
- 학생용에는 W1의 `정답 확인`을 제외하고 원본 정답 번호와 정답 근거를 노출하지 않는다.
- 오답 풀이가 지문분석본에 있으면 반영하고, 없으면 자료 밖 오답 설명을 새로 만들지 않는다.

### 8.3 WORDS & EXPRESSIONS

- 지문분석본의 WORDS & EXPRESSIONS를 기본 어휘 목록으로 삼는다.
- W1 강조 어휘와 WORKBOOK 어휘를 대조한다.
- 어휘 미니 테스트를 만들 때도 이 목록 안에서만 출제한다.
- 한 단어가 여러 품사를 가지면 기존 자료 또는 문맥에서 확인되는 의미만 제시한다.
- 한국어 발음은 어휘용 AGENTS의 방식에 따라 교실 친화적인 콩글리시식 표기로 쓴다.
- W1의 본문 어휘 강조는 위 목록에만 한정하지 않는다. 기존 해석본 규칙에 따라 원문 모든 문장을 전수 검토하고, 정답 판단·주제 이해·문장 구조 파악에 중요한 B2 이상 또는 학술·추상·전문 어휘를 문장별 1~3개 선정한다.

### 8.4 의미 단위 해석

W1은 의미 단위 해석을 보조적으로 사용하는 단계가 아니다. `../해석본 agent/AGENTS.md`의 해석본 전체 기능을 먼저 수행하고, 완성된 해석본 파트를 워크북에 그대로 이식한다. 해당 파일의 최신 해석·어휘·시각 품질 게이트와 브라우저 검수 규칙까지 자동으로 승계하며, 아래 규칙은 요약 적용이 아니라 모두 필수다.

#### 8.4.1 원문 확정

- 영어 원문의 단어, 문장부호, 대소문자, 줄 순서, 빈칸·밑줄 위치를 임의로 고치지 않는다.
- 이미지·스캔 입력은 1차 육안 판독, 2차 OCR 또는 기존 텍스트 대조, 3차 출력 HTML 태그 제거 원문 대조를 모두 수행한다.
- 의미 단위 표시, 핵심 동사 표시, 어휘 강조는 원문을 수정하지 않고 HTML 태그로만 감싼다.
- 빈칸 문항은 정답 확정 후 원래 빈칸 위치에만 `<span class="answer-fill">정답</span>`을 넣고 불필요한 밑줄을 남기지 않는다.

#### 8.4.2 어디서 끊는지

- 각 문장을 주어 / 핵심 동사 / 목적어 / 보어 / 부사구·부사절 단위로 충분히 나눈다.
- 각 의미 단위는 슬래시(`/`)로 구분한다.
- 형용사나 형용사구가 목적어를 수식하면 목적어와 함께 묶는다.
- 관계사절이 목적어를 수식하면 가능하면 목적어와 함께 묶는다.
- 부사구·형용사구·부사절·형용사절을 표시하려고 원문에 소괄호나 대괄호를 새로 넣지 않는다.
- 쉼표나 접속사만을 기준으로 기계 분절하지 않는다. 주어·서술어·목적어·보어·부사 성분이 화면에서 대응되도록 문장 구조를 먼저 판별한다.
- 핵심 서술어가 없는 수식구나 목적어 조각을 독립 행으로 떼지 않는다. 앞뒤 문장 성분과 합쳐 준동사에 억지로 밑줄을 긋지 않는다.
- 빈 단위, 맨 앞·맨 뒤 슬래시, 구두점이나 접속사만 있는 단위를 만들지 않는다.

#### 8.4.3 어떻게 해석하는지

- 데이터는 영어 `en` 한 줄과 한국어 `hint` 한 줄로 작성한다.
- `hint`는 한국어로만 작성한다. 일반 단어는 한국어 의미로 번역하고, 자연스러운 번역이 어려운 인명·지명·브랜드명·역사 용어·음식명은 한글 음차로 옮긴다.
- `en`과 `hint`의 슬래시 개수와 같은 인덱스의 의미가 반드시 1:1로 대응해야 한다.
- 영어의 뒤 단위 의미를 자연스러운 한국어 어순을 이유로 앞 한국어 단위에 옮기지 않는다.
- 영어 단위가 `동사 + 목적어`, `동사 + 보어`, `동사 + that절`처럼 동사가 먼저 나오면 한국어도 `사용한다 실험 설계를`, `작성했다 설문지를`, `형성했다 구성 요소를`처럼 동사 해석을 먼저 둔다.
- 쉼표·접속사·긴 한국어 구절 때문에 한국어 슬래시를 추가하지 않는다. 슬래시는 영어 의미 경계에 대응할 때만 쓴다.
- 슬래시는 `<span>`, `<strong>`, `<span class="answer-fill">` 등 HTML 태그 내부에 넣지 않는다.
- `hint`는 해설이 아니라 원문 해석이다. `도입`, `예시`, `대조`, `주장`, `결론`, `이 말은`, `여기서는` 같은 메타 설명을 넣지 않는다.
- 원문의 주체·동작·대상·정도·부정·비교·인과·양보·조건 관계를 빠뜨리거나 바꾸지 않는다.
- 각 영어 단위 바로 아래에 해당 한국어 단위를 작은 글씨로 중앙 정렬해 붙인다. 별도의 오른쪽 해석 칸은 만들지 않는다.

#### 8.4.4 핵심 동사를 찾고 표시하는 법

- 영어와 한국어 모두 문장 골격을 이루는 핵심 동사 또는 동사구만 굵게 표시한다.
- 핵심 동사는 품사가 아니라 문장 성분 기준으로 판별한다. 주어와 직접 호응하는 서술어, 목적어절·보어절 안에서 자체 주어와 호응하는 서술어만 표시한다.
- 전치사 뒤 동명사, 명사를 수식하는 현재분사·과거분사, 형용사화된 분사, 목적·수식용 부정사는 핵심 동사로 표시하지 않는다.
- `is`, `are`, `have`, `do`, `-ing`, `-ed`, `to V` 등을 정규식으로 일괄 강조하지 않는다. 문장마다 핵심 동사 목록을 먼저 확정한 뒤 정확한 어구만 태그로 감싼다.
- 영어 핵심 동사는 검정 굵은 글씨와 밑줄을 기본으로 하고, 동사 자체가 B2 이상 어휘이면 해당 어휘 색을 유지할 수 있다.

#### 8.4.5 어려운 단어를 찾고 표시하는 법

- 원문의 모든 문장을 개별 검토한다. 지문당 대표 단어 몇 개만 고르고 나머지 문장을 건너뛰면 실패다.
- B2·C1·C2 수준 어휘 또는 학생이 어려워할 학술·추상·전문 어휘 중 정답 판단, 주제 이해, 문장 구조 파악에 중요한 핵심 1~3개를 문장별로 고른다.
- 한 문장에 4개 이상 표시하지 않는다. 서로 다른 어려운 단어에 같은 `vocab-N` 클래스를 중복 사용하지 않는다.
- 영어는 `<span class="vocab vocab-N gloss" data-meaning="한국어 뜻">원래 단어</span>` 형식으로 감싸고, 원래 철자를 바꾸지 않는다.
- 한국어 `hint`의 대응 단어나 짧은 구에도 같은 `vocab-N` 클래스를 사용한다. 한 영어 단어가 한국어 한 단어로 대응되지 않으면 가장 가까운 짧은 한국어 구를 강조한다.
- 어휘 색상은 빨강과 검정을 피하고 파랑·초록·보라·청록·황토색 등 비빨간 계열을 사용한다. 흑백 인쇄에서도 굵기로 구분되어야 한다.
- 일반 고등학교 모의고사 지문은 어휘가 표시된 문장이 전체 문장의 절반 미만이면 전수 검토 누락 가능성으로 보고 다시 검토한다.

#### 8.4.6 주제와 정답

- 지문 전체의 핵심 주장·요지와 정답 선택지 성격을 반영해 `topic`을 한 문장으로 직접 확정하고 `주제 한 문장` 칸에 표시한다.
- 빈칸, 밑줄 의미, 문장 순서, 문장 삽입, 어색한 문장, 요약문, 제목·주제·요지 유형은 `answer`에 선택지 번호와 핵심 답안을 함께 넣고 `정답 확인` 칸에 표시한다.
- 빈칸·순서·삽입·어색한 문장 등 추론형은 원문·선택지 대조, 논리와 연결어 검토, `topic`·`hint`·`answer` 방향 일치 검토의 3회를 모두 수행한다.

#### 8.4.7 W1 렌더링 기능

- 표는 `No.`와 `원문 의미 단위` 2열만 사용한다. `흐름`, `처음`, `중간`, `끝`, `뜻 작성` 열을 렌더링하지 않는다.
- 영어 원문은 11pt, `"Inter", -apple-system, BlinkMacSystemFont, "SF Pro Text"`, 일반체, 줄간격 1.32를 기본으로 한다.
- 한국어 단위 해석은 `"Noto Sans KR"`, 7.8pt, 굵기 500, 줄간격 1.22, 중앙 정렬을 기본으로 한다.
- 핵심 동사와 B2 이상 어휘는 굵기 700으로 일반 본문과 구분한다.
- 지문 번호·학년·단계명 칩에만 포인트 빨강을 사용하고, 주제·정답·표 번호·원문·해석 본문에는 빨강을 쓰지 않는다.
- 하단 우측 전용 푸터 행에 윤조교 로고를 폭 약 16mm, 불투명도 약 0.72로 배치하고 본문을 가리지 않는다.
- 한 지문은 우선 A4 한 페이지에 맞추되 글자·행·주제·정답·푸터가 잘리면 의미 흐름 지점에서 2페이지로 나누고 `1/2`, `2/2`를 표시한다.

#### 8.4.8 W1 자동 검수

- 태그를 제거한 `en` 전체가 확정 원문과 정확히 일치하는지 검사한다.
- 각 unit의 `en.split("/")`와 `hint.split("/")` 길이와 같은 인덱스 의미 대응을 모두 검사한다.
- 가능하면 `worksheet번호, unit번호, segment번호, en_segment, hint_segment` 대조표를 임시 TSV로 만든다.
- 태그 내부 슬래시, 빈 단위, 구두점만 있는 단위가 없는지 검사한다.
- 동사+목적어·보어·that절의 한국어 단서가 동사 해석부터 시작하는지 검사한다.
- 핵심 동사 과잉 표시와 준동사 오표시를 문장별로 검사한다.
- 영어 어휘와 한국어 대응 어휘의 개수·색 클래스가 일치하고 문장별 강조가 3개 이하인지 검사한다.
- `hint`, `topic`, 한국어 설명문에서 예외 없는 영어 알파벳이 남지 않았는지 검사한다.
- `topic`, `answer`, 원문 빈칸 채움, 해석 방향이 서로 모순되지 않는지 검사한다.
- W1 해석본 검증이 하나라도 실패하면 CSS로 숨기지 말고 `en`·`hint`·어휘·동사·주제·정답 데이터를 수정한 뒤 다시 검사한다.

## 9. HTML 디자인 레이아웃 규칙

### 9.1 템플릿 사용

`html(디자인 레이아웃)/`에서 제공된 템플릿을 우선 사용한다.

찾는 순서:

1. `문제_템플릿.html`, `해설_템플릿.html`
2. `problem_template.html`, `solution_template.html`, `answer_template.html`
3. `index.template.html`
4. `index.html`
5. 기타 제공 HTML 템플릿

제공 템플릿이 있으면 그 구조를 유지한다. 템플릿에 없는 장식, 색상 체계, 인터랙티브 UI를 새로 만들지 않는다.

### 9.2 문제 HTML

`문제.html`에는 다음만 들어간다.

- 시험명, 학년, 번호 범위, 지문 번호
- W1·W4·W6·W7·W8·W9·W10
- 원문, 작성란, 선택지, 배열 제시어, 영작 제시어
- 어휘 테스트가 있으면 영어 단어와 발음·뜻 작성란
- 정답을 노출하지 않는 최소 힌트

`문제.html`에 들어가면 안 되는 것:

```text
정답
해설
정답 번호
오답 이유
배열 정답
오류 수정 답
영작 정답
어휘 발음·뜻 정답
answer-fill
correct-answer
data-answer
숨김 answer table
JavaScript answer data
HTML 주석 속 정답
source map 속 정답
```

### 9.3 해설 HTML

`해설.html`에는 다음이 들어간다.

- 원본 문항 정답과 근거
- W4 해석 정답
- W6 어법·어휘 정답과 근거
- W7 오류 수정 답과 근거
- W8 배열 정답과 근거
- W9 배열 정답과 근거
- W10 영작 정답과 근거
- 어휘 발음·뜻 정답표
- 8개 허용 문법 안의 보충 설명

W2·W3·W5의 독립 단계와 정답은 넣지 않는다.

### 9.4 인쇄 설정

- A4 세로 기준을 유지한다.
- 각 인쇄 페이지는 `width: 210mm`, `height: 297mm`를 기준으로 한다.
- 페이지 컨테이너에는 `break-inside: avoid`, `page-break-inside: avoid`를 적용한다.
- 표, 필기선, 선택지, 긴 문장, 해설 박스가 잘리지 않게 한다.
- 외부 CDN, 인터넷 폰트, 원격 이미지를 사용하지 않는다.
- 폰트 파일을 사용자에게 제공하지 않는다.

## 10. PDF 생성 규칙

1. `문제.pdf`는 반드시 최종 `문제.html`에서 생성한다.
2. `해설.pdf`는 반드시 최종 `해설.html`에서 생성한다.
3. PDF만 만들고 HTML을 생략하면 실패다.
4. HTML 수정 후에는 PDF를 다시 생성한다.
5. PDF 생성 후 첫 페이지와 마지막 페이지를 열어 렌더링을 확인한다.
6. HTML과 PDF 내용이 다르면 HTML을 기준으로 고치고 PDF를 재생성한다.

검수 항목:

- [ ] A4 세로 페이지가 유지된다.
- [ ] 빈 페이지가 없다.
- [ ] 표와 필기선이 잘리지 않는다.
- [ ] 글자 겹침이 없다.
- [ ] 한글, 영어 특수문자, 아포스트로피, 하이픈이 깨지지 않는다.
- [ ] 문제 PDF에는 W1의 `정답 확인`만 표시되고 W1 이외 단계의 정답은 노출되지 않는다.
- [ ] 해설 PDF에 정답과 근거가 누락되지 않는다.
- [ ] 어휘 테스트가 있으면 2열 13행 구조가 유지된다.

## 11. 자동 검수 규칙

### 11.1 유지 7단계 포함 검수

각 지문에 아래 단계가 모두 있어야 한다.

- [ ] WORKBOOK 1 지문 연습하기
- [ ] WORKBOOK 4 해석 연습하기
- [ ] WORKBOOK 6 어법·어휘 고르기
- [ ] WORKBOOK 7 어색한 곳 찾아 고쳐 쓰기
- [ ] WORKBOOK 8 순서 배열하기
- [ ] WORKBOOK 9 문단 배열하기
- [ ] WORKBOOK 10 영작 연습하기

### 11.2 제거 단계 혼입 검수

최종 산출물의 제목, 목차, 본문, 정답부, 파일명에 W2·W3·W5 관련 독립 단계가 있으면 실패다.

### 11.3 문법 화이트리스트 검수

- [ ] W6, W7, W10 해설의 모든 문법 라벨이 8개 허용 요소 안에 있다.
- [ ] CHECK를 선택지 쌍별로 분해했다.
- [ ] 금지 문법이 독립 문항이나 Grammar+로 들어가지 않았다.
- [ ] `to부정사 / -ing` 문항은 목적어로 해당 형태를 반드시 받는 동사·표현인지 확인했다.

### 11.4 기존 자료 포함·외부 요소 배제 검수

Source Coverage Ledger를 기준으로 확인한다.

- [ ] 7.0 단계별 세부 항목 보존 인벤토리의 필수 항목이 모두 Ledger에 등록되어 있다.
- [ ] 기존 자료의 유지 7단계 요소가 모두 Ledger에 등록되어 있다.
- [ ] Ledger의 `included` 요소가 문제지 또는 해설지에 반영되어 있다.
- [ ] Ledger의 `excluded` 요소가 산출물에 들어가지 않았다.
- [ ] 출력물의 모든 문제·해설·어휘·문법·배열·영작 요소가 Ledger와 연결된다. W1의 `en`·`hint`·핵심 동사·B2 어휘·`topic`·`answer`는 `W1 해석본 파생 데이터`로 연결한다.
- [ ] 자료 밖 예문, 외부 배경지식, 임의 문제 유형, W1 이외의 임의 어휘, 임의 디자인 장식이 없다.
- [ ] W1의 `정답 확인`은 화면에 직접 표시되고, W1 이외 학생용 정답은 숨김 데이터로도 들어가지 않았다.

### 11.5 원문·해석 검수

- [ ] 영어 원문이 원본 문제 또는 확정 원문과 일치한다.
- [ ] 한국어 해석이 지문분석본 또는 WORKBOOK 해석과 의미상 부합한다.
- [ ] 수치, 날짜, 조건, 인과, 대조, 부정 표현이 누락되지 않았다.
- [ ] 의미 단위 `en`과 `hint`를 사용할 경우 슬래시 개수와 의미 인덱스가 일치한다.
- [ ] 태그 내부에 슬래시가 들어가지 않았다.

### 11.6 정답 검수

추론형 또는 정답 판단이 필요한 문항은 3회 점검한다.

1. 원문, 선택지, 빈칸·밑줄·삽입 위치 확인
2. 논리 흐름, 지시어, 연결어, 반복어, 대조어 확인
3. `topic`, `answer`, `해석`, `정답 근거`, W1, W4, W6, W7, W8, W9, W10의 방향 일치 확인

### 11.7 학생용 정답 노출 검수

학생용 `문제.html`과 `문제.pdf`에는 W1 해석본의 화면 표시용 `topic`·`answer`를 제외한 실제 정답 데이터가 직접·간접으로 노출되면 실패다.

특히 아래를 검색한다.

```text
정답
해설
answer-fill
correct-answer
data-answer
배열 정답
오류 수정 정답
영작 정답
[정답]
Pron.
Meaning
```

단, 문제 지시문에서 “정답을 쓰시오”처럼 일반 표현으로 쓰이는 경우와 W1의 `주제 한 문장`·`정답 확인`은 허용한다. W1 이외 단계에서 실제 답안이나 정답 번호가 노출되면 실패다.

### 11.8 필수 4파일 검수

아래 네 파일이 모두 존재하고 비어 있지 않아야 한다.

```bash
test -s "outputs/<작업폴더명>/문제.html"
test -s "outputs/<작업폴더명>/문제.pdf"
test -s "outputs/<작업폴더명>/해설.html"
test -s "outputs/<작업폴더명>/해설.pdf"
```

### 11.9 최종 게이트 검수

완료 보고 전 아래 순서로 멈춤 검수를 수행한다.

1. 입력 게이트: `inputs/` 자료와 채팅 자료를 모두 확인했다.
2. 저장 경로 게이트: `outputs/<작업폴더명>/`이 입력 파일명 또는 채팅 자료명에 근거해 생성되었다.
3. 디자인 게이트: `html(디자인 레이아웃)/`의 레이아웃을 확인하고 적용했다.
4. 소스 커버리지 게이트: Source Coverage Ledger가 있고 출력 요소가 Ledger와 연결된다.
5. 구성 게이트: W1·W4·W6·W7·W8·W9·W10이 모두 있다.
6. 제거 게이트: W2·W3·W5가 독립 단계로 남아 있지 않다.
7. 문법 게이트: 모든 문법 문항과 해설이 8개 허용 요소 안에 있다.
8. 어휘 게이트: 모든 어휘 문항이 기존 자료에 출처가 있다.
9. 원문 게이트: 태그 제거 영어 원문이 원본 문제 또는 확정 원문과 일치한다.
10. 정답 게이트: 원본 정답, WORKBOOK 정답, 해설 근거가 충돌하지 않는다.
11. 문제지 게이트: W1 해석본의 `정답 확인`을 제외하고 학생용에 정답이 노출되지 않는다.
12. 해설지 게이트: 해설지에 정답과 근거가 모두 있다.
13. HTML 게이트: `문제.html`과 `해설.html`이 역할상 분리되어 있다.
14. PDF 게이트: `문제.pdf`와 `해설.pdf`가 최신 HTML에서 생성되었고 정상 렌더링된다.
15. 단계별 세부 항목 게이트: W1·W4·W6·W7·W8·W9·W10의 세부 항목 인벤토리가 산출물에 반영되었다.
16. 외부 요소 배제 게이트: 기존 자료 밖 요소가 없다.
17. 보고 게이트: 작업 폴더명과 필수 4개 파일명을 보고한다.

## 12. 실패 시 수정 원칙

실패 항목이 있으면 아래 순서로 수정한다.

1. 외부 요소 오류: Ledger에 없는 문항·어휘·예문·해설·디자인 요소 삭제
2. 누락 오류: 기존 자료의 `included` 요소 복구
3. 제거 단계 오류: W2·W3·W5 독립 단계 삭제
4. 문법 오류: 8개 허용 문법 밖 문항·해설 삭제
5. 어휘 오류: 원문·WORDS & EXPRESSIONS 밖 어휘 삭제
6. 원문 오류: 원본 문제와 대조해 복구
7. 정답 오류: WORKBOOK 정답부와 지문분석본 정답 재대조
8. 레이아웃 오류: 제공 템플릿 기준으로 복구
9. PDF 오류: HTML 수정 후 PDF 재생성

## 13. 최종 보고 형식

작업 완료 보고에는 아래 정보를 포함한다.

```text
완료했습니다.

저장 위치:
outputs/<작업폴더명>/

필수 산출물:
- 문제.html
- 문제.pdf
- 해설.html
- 해설.pdf

검수 결과:
- 유지 7단계 포함 확인
- W2·W3·W5 제거 확인
- 문법 8요소 제한 확인
- 기존 자료 요소 포함 확인
- 기존 자료 밖 요소 없음 확인
- W1 `정답 확인` 표시 및 W1 이외 학생용 정답 비노출 확인
- PDF 렌더링 확인
```

사용자가 요청하지 않은 추가 파일은 보고하지도 만들지도 않는다.
