# 워크북 의미 판단 기준

버전: 1.0.0  
적용 대상: 사람이 판단해야 하는 원문·번역·직독직해·서술어·어휘·오답·제시어

기계적으로 확인할 수 있는 단계 순서, 문항 수, 번호, `part`, 답 개수, 원문 복원, HTML/PDF 넘침은 `config/workbook-spec.json`과 validator가 담당한다. 이 문서는 자동 검사만으로 확정할 수 없는 판단에만 사용한다.

## 1. 원문 확정

- 영어 단어, 대소문자, 문장부호, 빈칸, 선택지, 지문 번호를 선명한 원본에서 확인한다.
- 한 글자라도 두 해석이 가능하면 추측하지 않는다. 정본 생성을 멈추고 더 선명한 자료를 요청한다.
- `source`는 확인된 원문을 보존한다. 승인된 표시용 차이가 있을 때만 `display`를 사용하며, 차이를 업데이트 보고서에 기록한다.
- HTML 태그, CSS 클래스, 슬래시 구분 문자열을 정본 텍스트에 넣지 않는다.

## 2. 자연스러운 완성 번역

- `translation`은 원문의 정보, 논리 관계, 시제, 태, 부정, 수식 범위를 빠뜨리지 않은 자연스러운 한국어 문장이다.
- 목적어를 동사보다 먼저 두는 일반적인 한국어 어순은 `translation`에서 허용한다.
- 인명·지명·브랜드명·역사 용어·음식명은 통용되는 한글 표기를 우선한다.
- 직역 때문에 뜻이 왜곡되거나, 자연스럽게 만들기 위해 원문 정보를 추가·삭제하면 실패다.

## 3. 직독직해 의미 단위

각 `meaningSegments[]`의 `en`과 `ko`는 같은 인덱스에서 정확히 하나의 의미를 대응한다.

- 영어는 주어 / 서술어 / 목적어·보어 / 부사구·부사절 / 관계사절 등 실제 문장 구조가 드러나는 크기로 나눈다.
- 긴 목적어절·관계사절·부사절을 한 단위에 뭉치지 않는다. 8단어 이상 문장은 원칙적으로 둘 이상으로 나누고, 한 단위가 16단어를 넘으면 다시 검토한다.
- 영어 조각을 순서대로 한 칸씩 이어 붙였을 때 `display` 또는 `source`의 단어, 대소문자, 문장부호가 그대로 복원되어야 한다.
- 빈 단위, 문장부호만 있는 단위, 접속사만 있는 단위, 맨 앞·맨 뒤의 빈 구간은 만들지 않는다.
- 한국어 단서는 자연스러운 완성 번역보다 영어 어순 대응을 우선한다. `동사 + 목적어·보어·절`이면 한국어도 `동사 뜻 + 목적어·보어·절 뜻` 순서로 둔다.
- 앞 단위의 목적어나 부사구를 뒤 단위로 넘기거나, 뒤 단위의 동사 뜻을 앞 단위로 당기지 않는다.
- `ko`에는 영어 알파벳을 남기지 않는다. 고유명사는 한글 음차로 쓴다.
- `도입`, `전개`, `예시`, `대조`, `강조`, `결론`, `즉`, `다시 말해`, `이 말은`, `여기서는` 같은 해설용 메타 표현을 넣지 않는다.

예시:

```text
en: use experimental designs
ko: 사용한다 실험 설계를
```

`실험 설계를 사용한다`는 완성 번역에는 가능하지만 같은 직독직해 단서에는 부적합하다.

## 4. 핵심 서술어 판단

- 실제 절의 주어에 대해 시제·태·양태·상태를 서술하는 중심 동사를 표시한다.
- 조동사, 수동태, 완료·진행형, 부정, 구동사는 뜻을 이루는 범위가 보이도록 함께 묶는다.
- `does ... come from`처럼 서술어 요소가 떨어져 있으면 여러 target으로 한 predicate를 표현한다.
- 주절뿐 아니라 내포절·관계절·부사절의 중심 서술어도 문장 구조 이해에 필요하면 표시한다.
- 전치사 뒤 동명사, 명사를 꾸미는 분사, 형용사화된 분사, 목적·수식용 부정사는 서술어로 표시하지 않는다.
- 보충어 부정사가 절의 핵심 의미를 실제로 담당하는지는 문맥으로 판단하며, 동사 모양이라는 이유만으로 기계적으로 표시하지 않는다.
- 영어와 한국어 target은 각각 해당 의미 단위 안에서 정확히 찾아져야 한다.

## 5. 어려운 어휘 판단

다음 중 하나 이상에 해당하고 학습 가치가 큰 어휘를 고른다.

- CEFR B2 이상으로 판단되는 어휘
- 학술·추상·전문 어휘
- 중등 학습자가 문맥만으로 이해하기 어려운 어휘
- 주제, 정답, 문장 구조를 이해하는 데 중요한 핵심어

적용 원칙:

- 한 문장당 0~3개만 선택한다. 많을 때는 주제·정답·구조 이해에 중요한 순서로 줄인다.
- 영어 target과 가장 가까운 한국어 뜻 target을 같은 annotation으로 연결한다.
- 한 의미 단위 안의 서로 다른 어휘에는 서로 다른 `colorSlot`을 쓴다.
- `meaning`은 짧고 문맥에 맞는 한국어 뜻으로 쓰며 일반 영어 단어를 남기지 않는다.
- 색상은 의미 판단이 아니라 renderer의 책임이다. 정본에는 `<span>`, `vocab-N`, `data-meaning`을 넣지 않는다.
- 어려운 어휘 표시는 최종 출력의 1단계에만 나타나며 답지 정답 빨강과 섞이지 않는다.

## 6. 문장 단위 연습 판단

- 2·3단계 빈칸은 문맥, 핵심 의미, 구조 학습에 가치 있는 부분을 고른다. 문장부호나 의미 없는 기능어만 빈칸으로 만들지 않는다.
- `baseText`는 기존에 승인된 축약·재표현 문항을 보존할 때만 사용한다. 새 문항은 기본 원문 또는 번역을 우선한다.
- 5단계의 `target.text`는 실제 정답 표면형이고 `cue`는 학생에게 보이는 기본형·어구다. 단순 접미사 제거로 기본형을 만들지 말고 수동태, 불규칙 변화, 조동사, 부정을 직접 확인한다.
- 6단계 오답은 문맥상 그럴듯하지만 문법·어휘상 명확히 하나만 틀려야 한다. 정답도 가능한 오답, 지나치게 황당한 오답, 원문 의미를 여러 방식으로 바꾸는 오답은 피한다.
- 8단계 chunk는 정답 순서로 이어 붙였을 때 원문의 단어, 대소문자, 문장부호를 그대로 복원한다. 제시 순서만 별도로 섞는다.
- 10단계 제시어는 핵심 표현을 떠올릴 만큼 충분하되 영어 골격 문장 자체를 제공하지 않는다.
- 문장 단위 단계는 대표 문장만 고르지 않고 모든 원문 문장을 한 번씩 포함한다.

## 7. 지문 단위 활동 판단

- 7단계는 정답 원문을 기준으로 오류 하나마다 안정적인 target ID를 둔다. 오답은 한 가지 방식으로 명확히 고칠 수 있어야 한다.
- 7단계 `textOverride`는 승인된 기존 축약 지문을 보존할 때만 사용한다. 새 콘텐츠를 조용히 추가하거나 원문 오류를 숨기는 용도로 쓰지 않는다.
- 9단계 block은 문단의 시간·인과·대조·지시어 흐름이 학습 가능하도록 나눈다.
- 새 9단계 문항에서는 선택지 표기가 위에서 아래로 `(A)`, `(B)`, `(C)` 순서여야 한다. `blocks` 배열에 **섞어서 제시할 내용**을 A·B·C 순서로 넣고 `displayOrder`를 `[1,2,3]`(canonical은 `["A","B","C"]`)으로 둔다. `displayOrder`를 뒤집어 C·B·A로 인쇄하지 않는다.
- `answerOrder`는 제시된 블록을 원문 순서로 복원할 때의 **선택지 문자 순서**다. `blocks` 배열 순서를 정답으로 간주하지 않는다. 예를 들어 A=원문 3단락, B=원문 2단락, C=원문 1단락이면 정답은 C-B-A다.
- 새 문항의 모든 원문 문장을 `blocks`에 정확히 한 번씩 넣는다. 일부 문장만 배열하고 앞뒤를 `fixedIntroSentenceIds`·`fixedOutroSentenceIds`로 고정하지 않는다.
- 이미 A-B-C로 놓인 선택지를 그대로 답으로 쓰지 않는다. 여러 지문을 한 묶음으로 작성할 때는 가능한 범위에서 정답 순열을 문항마다 다르게 설계한다. 다섯 개의 3블록 문항이면 A-B-C를 제외한 다섯 순열을 각각 한 번씩 쓸 수 있다.
- 기존 검토 정본의 순서와 출력은 소급 변경하지 않는다. 이 규칙은 새 authoring packet의 작성·검수에 적용한다.

## 8. 최종 의미 검수

다음 질문에 모두 `예`일 때만 의미 검수를 통과시킨다.

1. 원문을 추측한 곳이 없는가?
2. 자연스러운 번역과 직독직해 단서의 역할이 분리되어 있는가?
3. 모든 의미 단위가 같은 인덱스에서 1:1로 대응하는가?
4. 서술어 표시는 문장 성분 판단에 근거하는가?
5. 어려운 어휘가 문장당 3개 이하이고 영어·한국어 뜻이 정확히 연결되는가?
6. 동사 cue와 어법·어휘 오답을 사람이 문맥 속에서 확인했는가?
7. 빈칸·선택·배열 정답을 복원하면 승인된 base text 또는 원문과 일치하는가?
8. 기존 콘텐츠와 달라진 판단이 있다면 contentVersion과 업데이트 보고서에 남겼는가?

애매한 항목은 통과로 간주하지 않는다. 해당 문장과 경고만 작은 검토 묶음으로 다시 판단하고, 해결되지 않은 경고가 0개일 때 release한다.
